Title: Supplier Setup, Raw Materials & Supplies Rename, Purchases/Expenses Logic, Closing Recreate Action, Payroll Expense Integration, and Setup UI Improvements

We need to implement several final cleanup and workflow improvements in the Water Company app.

These changes focus on suppliers, purchases, expenses, payroll, daily closing, inventory naming, and setup page usability.

Please implement the changes below.

---

## 1. Add Suppliers Setup Module

Add a Suppliers feature to the app.

A supplier represents any person, vendor, company, or service provider the water company buys from or pays.

Suppliers should be usable across:

* Raw Materials & Supplies purchases
* Inventory purchases
* Expense entries
* Packaging purchases
* Spare part purchases
* Fuel purchases, where fuel is stocked
* Machine maintenance expenses
* Vehicle/fuel/repair expenses
* Production-related purchases
* Other business purchases

### Required behavior

Add Suppliers as:

* A setup tab under Water Company Setup
* A full Suppliers page
* A selectable dropdown on relevant purchase and expense forms

Supplier fields should include:

* SupplierId
* CompanyId
* SupplierName
* ContactPerson
* Phone
* Email
* Address
* SupplierType
* Notes
* IsActive
* CreatedBy
* CreatedAt
* UpdatedBy
* UpdatedAt

SupplierType examples:

* Raw Material Supplier
* Packaging Supplier
* Fuel Supplier
* Machine Parts Supplier
* Vehicle Repair Supplier
* Utility Provider
* Service Provider
* Other

The supplier dropdown should include:

* All active suppliers
* Option to add a new supplier quickly if needed
* Optional value such as “No Supplier / Other” if the user does not want to assign a supplier

## 2. Use Supplier as “Paid To” on Expenses

The Expenses page currently tracks expenses, but it should also clearly track who was paid.

Add Supplier/Paid To support on expense entries.

Expense form should include:

* Category
* Amount
* Payment method
* Supplier / Paid To
* Description
* Date
* Notes

The Supplier/Paid To field should use the Suppliers list.

Examples:

* Electricity expense → Supplier/Paid To = ECG
* Fuel expense → Supplier/Paid To = Goil Station
* Vehicle repair → Supplier/Paid To = Mechanic / Repair shop
* Machine maintenance → Supplier/Paid To = Machine technician
* Borehole maintenance → Supplier/Paid To = Borehole service provider

The Expenses list should show a “Paid To” column.

Expense reports should support filtering by Supplier/Paid To.

Keep the existing tabs:

Keep existing categories such as:

* PackagingRoll
* SachetFilm

* Fuel

“Track production materials, packaging items, spare parts, fuel kept in stock, cleaning supplies, and other stock-tracked supplies.”

Raw Materials & Supplies purchase form should include:

## 5. Clarify Stock Purchases vs Normal Expenses

The app should clearly separate stock-related purchases from normal expenses.

Use this rule:

`If the item is stored and tracked by quantity, it belongs in inventory / Raw Materials & Supplies / stock purchases.`

`If it is a service or immediate cost, it belongs on the Expenses page only.`

### Stock-tracked purchases

Examples:

* Rubber rolls
* Sachet film
* Outer bags
* Chemicals
* Filters
* UV lamps
* Spare parts kept in stock
* Fuel stored in quantity
* Cleaning supplies kept in stock
* Packaging materials

These should create:

* Purchase record
* Inventory stock-in
* Linked Expense/cash-out record

### Normal expenses

Examples:

* Electricity bill
* Fuel bought and used immediately
* Machine repair service
* Vehicle repair service
* Labor/wages
* Rent
* Government fees
* Phone/internet
* Loading boys
* Borehole maintenance service

These should create:

* Expense record only

They should not create inventory unless the purchased item is actually being stored and tracked as stock.

---

## 6. Payroll Should Create Linked Expense When Approved or Paid

Payroll is a real business cost and should feed the Expenses page.

When payroll is Draft, Pending, or Unapproved, do not create an expense yet.

When payroll is Approved or Marked as Paid, create one linked Expense record for the total payroll amount.

The expense should include:

* CompanyId
* ExpenseDate = Payroll payment date or approval date
* ExpenseCategory = Payroll / Salaries / Wages
* Amount = Total Payroll Amount
* PaymentMethod, if captured on payroll
* Description = Payroll for selected period/date range
* SourceType = Payroll
* SourceId = PayrollId
* CreatedBy
* CreatedAt

Do not create one expense per employee in the Expenses page.

The Payroll page should keep the employee-level payroll breakdown.

The Expenses page should show one summarized payroll expense for the payroll run.

Avoid duplicate payroll expenses.

If payroll is reversed, cancelled, or reopened, the linked expense should also be reversed, marked inactive, or updated consistently.

If payroll is corrected and reapproved, update or recreate the linked expense safely using:

* SourceType = Payroll
* SourceId = PayrollId

Payroll expenses should appear in Expense Reports, Profit/Loss Reports, Daily Summary Reports, and Closing Reports.

---

## 7. Daily Closing: Add Recreate/Recalculate Closing Action

The Daily Closing page already allows a closing to be reopened, viewed, and resubmitted.

However, after reopening a closing, the most important action is missing:

`Recreate / Recalculate Closing for This Day`

When a closing is reopened, the user must be able to regenerate the closing using the latest corrected data for the same date.

### Required behavior

When a user reopens a closing:

* Mark the old closing as Reopened, Superseded, or Inactive.
* Preserve the old closing in history.
* Show a clear action: Recreate Closing or Recalculate Closing.
* Recalculate the closing for that same date using current sales, payments, expenses, production, losses, deliveries, payroll, raw material purchases, and cash data.
* Allow the user to review the recalculated closing.
* Allow the user to submit the new closing.
* Mark the new closing as the active closing for that date.
* Link the new closing to the old closing if applicable.

Only one closing should be active for a given company and date.

The old closing should remain viewable for audit history.

Suggested fields:

* ClosingDate
* Status
* IsActive
* SupersededByClosingId
* ReopenedBy
* ReopenedAt
* ReopenReason
* RecalculatedBy
* RecalculatedAt
* SubmittedBy
* SubmittedAt

The closing details should clearly show whether the closing was original, reopened, superseded, or resubmitted.

Prompt part 2: Additional work - Populate Clickable Source Links for Auto-Generated Expense Records
Title: Additional work - Populate Clickable Source Links for Auto-Generated Expense Records


We need to fix the Source column on the Expenses page for expense records that are automatically created from other modules.

Currently, when expenses are auto-created from Raw Materials & Supplies purchases or Payroll, the expense record appears correctly, but the Source column is blank or shows “—”.

This is incorrect.

The Source column should show a clickable link back to the original record that created the expense.

Required behavior:

1. When a Raw Materials & Supplies purchase creates an Expense record, populate the expense source fields.

Use:
- SourceType = RawMaterialPurchase
- SourceId = RawMaterialPurchaseId
- SourceLabel = Raw Material Purchase or Raw Materials & Supplies Purchase
- SourceUrl = URL/path to the related raw material purchase details page or purchase record

On the Expenses page, the Source column should display a clickable link such as:

Raw Material Purchase

or

Raw Materials & Supplies Purchase

When clicked, it should open the related purchase details record.

2. When Payroll creates an Expense record, populate the expense source fields.

Use:
- SourceType = Payroll
- SourceId = PayrollId
- SourceLabel = Payroll
- SourceUrl = URL/path to the related payroll details page or payroll run

On the Expenses page, the Source column should display a clickable link such as:

Payroll

or

Payroll Run #4

When clicked, it should open the related payroll record.

3. Existing production-generated expenses already show “Production Batch” in the Source column. Keep that behavior.

Use the same pattern for Raw Materials & Supplies purchases and Payroll expenses.

4. The Expenses list should render Source as a clickable link when SourceType and SourceId exist.

If no source exists, show “—”.

5. The link should route to the correct details page based on SourceType.

Examples:
- SourceType = ProductionBatch → open production batch details
- SourceType = RawMaterialPurchase → open raw material purchase details
- SourceType = Payroll → open payroll details/payroll run

6. The source relationship should be stored in the database, not hardcoded only in the UI.

Each auto-generated expense should store:
- SourceType
- SourceId
- SourceLabel, if the system uses labels
- SourceUrl or enough data to build the route
- CompanyId

7. The Source column should also work in Expense Details and Expense Reports.

8. If the original source record is reversed, deleted, or marked inactive, the expense should still preserve the source reference for audit history.

9. Avoid duplicate or broken links.

10. Add or update existing expenses created from Raw Materials & Supplies purchases and Payroll where possible so their Source column is populated correctly.

Expected final behavior:

- Production batch expenses show a clickable Production Batch source.
- Raw Materials & Supplies purchase expenses show a clickable Raw Material Purchase source.
- Payroll expenses show a clickable Payroll source.
- Manual expenses with no source continue to show “—”.
- Clicking the source opens the related source record/details page.










Prompt part 3: Add Payroll Unapprove, Edit, Delete, and Linked Expense Reversal Workflow
Title: Add Payroll Unapprove, Edit, Delete, and Linked Expense Reversal Workflow

We need to improve the Payroll workflow so payroll runs can be corrected safely after approval/payment.

Currently, once a payroll run is approved/paid, the user can open it, but cannot unapprove it, edit it, or correct mistakes. Also, unapproved payroll runs cannot be deleted. This needs to be fixed.

Required changes:

1. Add payroll actions based on status.

For Draft / Pending / Unapproved payroll runs, show:
- Open / View Details
- Edit
- Approve / Mark as Paid
- Delete

For Approved / Paid payroll runs, show:
- Open / View Details
- Unapprove / Reopen
- Reverse, if that is the preferred wording

2. Allow unapproved payroll runs to be deleted.

If a payroll run is Draft, Pending, or Unapproved, allow the user to delete it.

Before deleting, show confirmation:

“Are you sure you want to delete this payroll run? This action will remove the payroll run and its employee payroll lines.”

Only allow delete if the payroll has not created any approved expense/cash impact.

3. Add Unapprove / Reopen action for approved payroll.

When the user clicks Unapprove/Reopen, show confirmation:

“Are you sure you want to reopen this payroll run? This will reverse or deactivate the linked payroll expense and allow the payroll to be edited again.”

Require a reason for reopening.

4. Reverse or deactivate the linked payroll expense.

When an approved/paid payroll is reopened, the linked Expense record created from payroll should be reversed, marked inactive, or cancelled.

Do not leave the payroll expense active if the payroll is no longer approved/paid.

Find the linked expense using:

- SourceType = Payroll
- SourceId = PayrollId

5. Allow editing after payroll is reopened.

After reopening, payroll status should become:

- Reopened
or
- Draft
or
- Pending

Use whichever status fits the existing system best.

The user should then be able to edit:
- Payroll period
- Employees included
- Employee wages/amounts
- Notes
- Payment method/cash account, if applicable

6. Allow reapproval after editing.

After corrections are made, the user should be able to approve/mark as paid again.

When reapproved:
- Recalculate gross and net totals.
- Create or reactivate the linked payroll expense.
- Ensure the expense amount matches the corrected payroll total.
- Ensure no duplicate payroll expense is created.

7. Avoid duplicate expense records.

One approved payroll run should have only one active linked payroll expense.

Use:

- SourceType = Payroll
- SourceId = PayrollId

If the payroll is reopened and reapproved, update the old linked expense or create a new active one while keeping the old one inactive/reversed for audit.

8. Add payroll audit trail.

Track:
- CreatedBy
- CreatedAt
- ApprovedBy
- ApprovedAt
- ReopenedBy
- ReopenedAt
- ReopenReason
- ReapprovedBy
- ReapprovedAt

Payroll details should show this history.

9. Payroll list should show clearer actions.

On the Payroll list page, replace only “Open” with a proper Actions area.

Suggested actions:

For Paid payroll:
- View Details
- Reopen

For Draft/Pending/Reopened payroll:
- View Details
- Edit
- Approve/Mark as Paid
- Delete

10. Payroll details page should show linked expense.

On payroll details, show:
- Payroll status
- Payroll period
- Gross total
- Net total
- Cash account/payment method
- Employee breakdown
- Linked expense, if approved/paid
- Reopen/reapproval history

The linked expense should be clickable and open the related Expense record.

Expected final behavior:

- Draft/Pending payroll can be edited or deleted.
- Approved/Paid payroll can be reopened/unapproved.
- Reopening payroll reverses or deactivates the linked expense.
- Reopened payroll can be edited and approved again.
- Reapproving payroll creates or updates the linked expense without duplicates.
- Payroll details show the full audit trail and linked expense.
